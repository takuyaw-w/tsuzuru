# v0.9 Tsuzuru Config Plan

Status: initial package, example config, and `tsuzuru check` CLI added.

`@tsuzuru/config` provides `defineTsuzuruConfig()` and the minimal config types
needed for future tooling. The first supported config shape is:

```ts
defineTsuzuruConfig({
  scenario: {
    entry: "scenario/main.tzr",
    files: ["scenario/**/*.tzr"],
  },
  plugins: [createStdVisualPlugin(), createStdAudioPlugin()],
});
```

`@tsuzuru/cli` provides the first config-consuming command:

```sh
tsuzuru check
```

It loads `tsuzuru.config.ts` from the current directory, expands
`scenario.files` relative to that config directory, reads the matched `.tzr`
files, and validates the project with `compileTzrProject()` using
`scenario.entry` and `plugins`.

Planned follow-up work:

- resolve defaults and validate config
- connect the config to future create-tsuzuru templates
- consider Vite integration without making `.tzr` glob patterns dynamic inside
  application code

Current constraints:

- Core does not read the file system.
- The example still uses `src/scenario.ts` and Vite `import.meta.glob` as the
  runtime adapter.
- `tsuzuru check` is the only implemented CLI command; `dev`, `build`, watch
  mode, Vite integration, and create-tsuzuru are still future work.
- The CLI only looks for `tsuzuru.config.ts` in the current directory.
- Title, load, settings, backlog, and gallery are still TSX / HTML host code.
- `.tzr` remains focused on scenario content after Start.
