# v0.3 std audio plugin 実装計画

> Status: historical implementation plan. References to legacy DSL syntax or
> removed examples predate the DSL v2 cleanup and are not current guidance.

このドキュメントは `@tsuzuru/plugin-std-audio` の作業用実装計画である。  
利用者向けの正式仕様書ではない。

利用者向け仕様は `docs/plugins/std-audio.md` に整理し、設計判断は `docs/history/decisions/0005-std-audio-plugin.md` に整理する。

---

## 1. 位置付け

`@tsuzuru/plugin-std-audio` は、Tsuzuru v0.3 scope として実装する公式 plugin である。

Core には含めないが、Tsuzuru 公式の標準 plugin として扱う。  
サンプル plugin ではなく、事実上の標準ライブラリに近い位置付けとする。

### package

```txt
packages/plugin-std-audio
```

### package name

```txt
@tsuzuru/plugin-std-audio
```

### 命名方針

公式提供 plugin は `std` 系の命名にする。

例:

```txt
@tsuzuru/plugin-std-audio
```

---

## 2. Core との境界

Core は、シナリオ実行・状態管理・制御フローを担当する。

`@startBgm` / `@stopBgm` / `@se` / `@voice` は Core command ではなく、plugin command として提供する。

理由:

- BGM / SE / Voice は rendering / presentation に近い責務である
- Core は `HTMLAudioElement` / Web Audio API / browser autoplay / asset path に依存しない方針である
- 将来的に別 renderer や別 audio implementation を許容しやすくするため
- audio playback は browser / runtime environment ごとの差が大きいため、Core に hardcode しない方がよい

---

## 3. plugin の責務

`@tsuzuru/plugin-std-audio` は renderer 非依存にする。

### やること

- `@startBgm` / `@stopBgm` / `@se` / `@voice` command を提供する
- audio state を `runtimeState.plugins.stdAudio` に保持する
- SE / Voice の一回性 event を state に積む
- command argument の schema validation を行う
- state 取得用 helper を提供する
- command schema と command handler factory を export する

### やらないこと

- `HTMLAudioElement` / Web Audio API は操作しない
- 音声を直接再生しない
- 音声を直接停止しない
- browser autoplay 制約への対応はしない
- asset resolver は内蔵しない
- assetId から音声 path / URL への変換は行わない
- volume / loop / fade / channel は v0.3 scope では扱わない
- `@stopSe` は提供しない
- `@startVoice` / `@stopVoice` は提供しない
- 実音声ファイルは package / example に同梱しない

---

## 4. asset 解決方針

`@tsuzuru/plugin-std-audio` は state に `assetId` のみを保存する。

assetId から実ファイル path / URL への変換は、app / renderer / example 側で行う。

例:

```ts
export const bgmAssets = {
  daily_theme: "/assets/audio/bgm/daily_theme.mp3",
} as const

export const seAssets = {
  door_open: "/assets/audio/se/door_open.mp3",
} as const

export const voiceAssets = {
  alice_001: "/assets/audio/voice/alice_001.mp3",
} as const
```

plugin state には resolved path を保存しない。

理由:

- scenario / runtime state を file layout に結合しない
- app ごとの asset map を許容する
- bundler / hosting / file format の違いを renderer / app 側に逃がせる
- save data の意味を asset path ではなく安定した `assetId` に寄せられる

---

## 5. runtime state

`@tsuzuru/plugin-std-audio` は、runtime state の plugin 領域に state を持つ。

```ts
runtimeState.plugins.stdAudio
```

plugin 側で独自 store は持たない。

理由:

- BGM は save/load 対象のゲーム状態である
- SE / Voice event も runtime の進行結果として state に記録する
- runtime state に集約した方が renderer / app 側が参照しやすい
- plugin 独自 store を持つと同期責務が増える

---

## 6. 初期 state

plugin 登録時に、以下の初期 state を用意する。

```ts
runtimeState.plugins.stdAudio = {
  bgm: null,
  seEvents: [],
  voiceEvents: [],
  nextSeSequence: 1,
  nextVoiceSequence: 1,
}
```

`bgm` は未設定状態を `null` で表す。

SE / Voice は現在状態ではなく、一回性 event として扱う。

## 8. bgm

`bgm` は文字列ではなくオブジェクトで保持する。

```ts
bgm: {
  assetId: "daily_theme",
}
```

理由:

- 将来 `volume` / `loop` / `fade` / `channel` などを追加しやすい
- v0.3 scope では `assetId` のみを持つ

未設定状態は `null` とする。

```ts
bgm: null
```

BGM は v0.3 scope では単数扱いとする。  
複数 BGM channel は扱わない。

---

## 9. seEvents

SE は一回性 event として `seEvents` に保持する。

```ts
seEvents: [
  {
    sequence: 1,
    assetId: "door_open",
  },
]
```

SE は現在状態ではない。  
同じ asset ID が連続して指定されても、常に新しい event として追加する。

```tzr
@se("door_open")
@se("door_open")
```

結果:

```ts
seEvents: [
  {
    sequence: 1,
    assetId: "door_open",
  },
  {
    sequence: 2,
    assetId: "door_open",
  },
]
```

renderer / app 側は `lastConsumedSeSequence` を保持し、未処理の event だけを再生する。

```ts
let lastConsumedSeSequence = 0

for (const event of audio.seEvents) {
  if (event.sequence > lastConsumedSeSequence) {
    playSe(event.assetId)
    lastConsumedSeSequence = event.sequence
  }
}
```

---

## 10. voiceEvents

Voice は一回性 event として `voiceEvents` に保持する。

```ts
voiceEvents: [
  {
    sequence: 1,
    assetId: "alice_001",
  },
]
```

Voice は BGM のような現在状態ではない。  
同じ asset ID が連続して指定されても、常に新しい event として追加する。

```tzr
@voice("alice_001")
@voice("alice_001")
```

結果:

```ts
voiceEvents: [
  {
    sequence: 1,
    assetId: "alice_001",
  },
  {
    sequence: 2,
    assetId: "alice_001",
  },
]
```

renderer / app 側は `lastConsumedVoiceSequence` を保持し、未処理の event だけを再生する。

```ts
let lastConsumedVoiceSequence = 0

for (const event of audio.voiceEvents) {
  if (event.sequence > lastConsumedVoiceSequence) {
    stopCurrentVoiceIfNeeded()
    playVoice(event.assetId)
    lastConsumedVoiceSequence = event.sequence
  }
}
```

前の voice を停止するか、重ねるか、最後まで流すかは renderer / app 側の責務とする。

plugin state に `currentVoice` は持たない。

---

## 11. sequence

`seEvents` / `voiceEvents` の event には `sequence` を持たせる。

```ts
{
  sequence: number,
  assetId: string,
}
```

`sequence` は event の発生順を表す。

初期値:

```ts
nextSeSequence: 1
nextVoiceSequence: 1
```

最初の event の `sequence` は `1` から始める。

renderer / app 側の consumed sequence は `0` 初期値で扱う。

```ts
let lastConsumedSeSequence = 0
let lastConsumedVoiceSequence = 0
```

`nextSeSequence` / `nextVoiceSequence` は state に保持する。  
将来 `seEvents` / `voiceEvents` を prune しても sequence が重複しないようにするためである。

---

## 12. event 型

v0.3 scope では、`seEvents` / `voiceEvents` の配列を分ける。

```ts
seEvents: StdAudioSeEvent[]
voiceEvents: StdAudioVoiceEvent[]
```

event object 自体に `type: "se"` / `type: "voice"` は持たせない。

理由:

- 配列名で event 種別が分かる
- runtime state に冗長な field を持たせない
- renderer / app 側で SE と Voice の処理を分けやすい

ただし、TypeScript の構造的部分型により `StdAudioSeEvent` と `StdAudioVoiceEvent` が相互代入されることを避けるため、branded type とする。

brand は runtime state には保存しない。

例:

```ts
declare const stdAudioSeEventBrand: unique symbol
declare const stdAudioVoiceEventBrand: unique symbol

export type StdAudioSeEvent = {
  sequence: number
  assetId: string
} & {
  readonly [stdAudioSeEventBrand]: never
}

export type StdAudioVoiceEvent = {
  sequence: number
  assetId: string
} & {
  readonly [stdAudioVoiceEventBrand]: never
}
```

生成箇所でのみ cast する。

```ts
const event = {
  sequence: state.nextSeSequence,
  assetId,
} as StdAudioSeEvent
```

## 14. `@startBgm`

### 構文

```tzr
@startBgm("daily_theme")
```

### 責務

`@startBgm` は、BGM asset ID を audio state に保存する。

### 引数

第1引数は暗黙的に `assetId` として扱う。

```tzr
@startBgm("daily_theme")
```

state 上では次のように正規化する。

```ts
bgm: {
  assetId: "daily_theme",
}
```

### 再指定

`@startBgm` は再指定時に常に `bgm` を上書き更新する。

```tzr
@startBgm("daily_theme")
@startBgm("battle_theme")
```

結果:

```ts
bgm: {
  assetId: "battle_theme",
}
```

同じ BGM asset ID を再指定した場合もエラーにしない。

```tzr
@startBgm("daily_theme")
@startBgm("daily_theme")
```

結果的に同じ値が再代入されるだけである。  
同一 BGM の再再生を抑制するかどうかは renderer / app 側の責務とする。

### 追加 option

`volume` / `loop` / `fade` / `channel` は v0.3 scope では扱わない。  
将来拡張として検討する。

---

## 15. `@stopBgm`

### 構文

```tzr
@stopBgm
```

### 責務

`@stopBgm` は、現在の BGM を停止する意図を表す。

plugin state 上では `bgm` を `null` にする。

```ts
bgm: null
```

### 引数

`@stopBgm` は引数なしのみ許可する。

```tzr
@stopBgm
```

以下は schema validation error とする。

```tzr
@stopBgm("daily_theme")
```

### bgm が null の場合

`bgm` が `null` の状態で `@stopBgm` を実行した場合は no-op とする。

runtime warning は出さない。

理由:

- `@stopBgm` は「現在の BGM を止める」命令である
- 対象指定がないため、止める対象がなくても異常とは言い切れない
- シナリオ上、安全に何度でも書ける

### 他 state への影響

`@stopBgm` は `bgm` だけを `null` にする。

`seEvents` / `voiceEvents` / `nextSeSequence` / `nextVoiceSequence` には影響しない。

## 18. validation

### 空文字 assetId

`assetId` の空文字は禁止する。

以下はすべて schema validation error とする。

```tzr
@startBgm("")
@se("")
@voice("")
```

### `@stopBgm` の引数

`@stopBgm` は引数なしのみ許可する。

以下は schema validation error とする。

```tzr
@stopBgm("daily_theme")
```

### 未対応追加引数

v0.3 scope では、未対応の追加引数を厳格に禁止する。

以下は schema validation error とする。

```tzr
@startBgm("daily_theme", volume=0.8)
@se("door_open", volume=0.8)
@voice("alice_001", volume=0.8)
```

未知 option は無視しない。

理由:

- scope を明確にする
- 未対応 option が効いているように見える誤解を防ぐ
- typo を早期に検出する

std-visual の `@hide("missing")` のように、指定した runtime target が存在しないことを検出する command が std-audio にはないためである。

## 20. save / load

BGM は現在状態なので save / load 対象にする。

SE / Voice は一回性 event なので、過去の event は load 後に再生されるべきではない。

そのため、save 時には `seEvents` / `voiceEvents` を空にする方針とする。

```ts
runtimeState.plugins.stdAudio = {
  bgm: currentBgm,
  seEvents: [],
  voiceEvents: [],
  nextSeSequence: currentNextSeSequence,
  nextVoiceSequence: currentNextVoiceSequence,
}
```

`nextSeSequence` / `nextVoiceSequence` は保持する。  
load 後も sequence が単調増加し続けるようにするためである。

### Current Core Limitation

現時点の Core snapshot API は、plugin state をそのまま clone する。  
plugin ごとの save serialization hook はまだない。

そのため、この save behavior を実装するには、次のいずれかが必要である。

```txt
- Core に plugin snapshot serialization hook を追加する
- std-audio 側に save 用 helper を提供し、app / save adapter 側で呼び出す
```

v0.3 scope では、save serialization 対応を別タスクとして扱う。

最初の skeleton 実装には含めない。

## 21. public API

### plugin command schema

`.tzr` compile 時に使う command schema を export する。

```ts
import { stdAudioPluginCommands } from "@tsuzuru/plugin-std-audio"
```

想定:

```ts
export const stdAudioPluginCommands = {
  startBgm: definePluginCommand("startBgm", {
    kind: "positional",
    arguments: [{ type: "string", nonEmpty: true }],
  }),
  stopBgm: definePluginCommand("stopBgm", {
    kind: "none",
  }),
  se: definePluginCommand("se", {
    kind: "positional",
    arguments: [{ type: "string", nonEmpty: true }],
  }),
  voice: definePluginCommand("voice", {
    kind: "positional",
    arguments: [{ type: "string", nonEmpty: true }],
  }),
} satisfies PluginCommandMap
```

### plugin factory

`@tsuzuru/plugin-std-audio` は factory 関数を export する。

```ts
import { createStdAudioPlugin } from "@tsuzuru/plugin-std-audio"

const runtimeState = createInitialRuntimeState(document, {
  plugins: [
    createStdAudioPlugin(),
  ],
})
```

将来的に plugin options を追加しやすい形にする。

```ts
createStdAudioPlugin({
  // future options
})
```

### command handlers

runtime 実行時に渡す command handler factory を export する。

```ts
import { createStdAudioCommandHandlers } from "@tsuzuru/plugin-std-audio"

const result = stepRuntime(document, runtimeState, {
  commandHandlers: createStdAudioCommandHandlers(),
})
```

### helper

renderer / app 側が state を扱いやすいように、薄い helper を提供する。

```ts
import { getStdAudioState } from "@tsuzuru/plugin-std-audio"

const audio = getStdAudioState(runtimeState)
```

`getStdAudioState(runtimeState)` は、`runtimeState.plugins.stdAudio` が未初期化の場合にエラーにする。

理由:

- plugin 未登録のまま renderer が stdAudio を読んでいる状態は設定ミスである
- 早期に検出した方がよい

## 22. export types

以下の runtime state 型を export する。

```ts
export type StdAudioState
export type StdAudioBgm
export type StdAudioSeEvent
export type StdAudioVoiceEvent
```

### 型名方針

`bgm` の型名は `StdAudioBgm` とする。  
`StdAudioBgmState` のような冗長名にはしない。

SE event の型名は `StdAudioSeEvent` とする。

Voice event の型名は `StdAudioVoiceEvent` とする。

`sequence` 専用型は作らない。  
`sequence` は `number` として扱う。

### 取得方針

型は公開するが、state 取得は基本的に `getStdAudioState(runtimeState)` の利用を推奨する。

### 実音声ファイル

v0.3 scope では、実音声ファイルは同梱しない。

理由:

- BGM / SE / Voice は著作権・ライセンス管理負荷が高い
- v0.3 の目的は audio plugin の state / event モデルを示すこと
- example のために素材選定で実装が止まるのを避ける

README に、ユーザーが任意の音声ファイルを配置する前提を明記する。

```txt
音声ファイルは同梱していません。
動作確認する場合は、任意の音声ファイルを以下に配置してください。

public/assets/audio/bgm/daily_theme.mp3
public/assets/audio/se/door_open.mp3
public/assets/audio/voice/alice_001.mp3
```

### asset map

assetId と音声 path の対応表は `src/assets.ts` にまとめる。

```txt
examples/preact-std-audio/src/assets.ts
```

`AudioLayer.tsx` 内へ直接書かず、再生責務と asset map を分離する。

例:


## 30. save serialization タスク

`seEvents` / `voiceEvents` は一回性 event なので、save 時に空にする。

ただし、現時点の Core snapshot API は plugin state をそのまま clone するため、plugin ごとの serialize hook がない。

対応案:

```txt
A. Core に plugin snapshot serialization hook を追加する
B. std-audio 側に save 用 helper を提供し、app / save adapter 側で呼び出す
```

v0.3 でどちらを採用するかは、実装時に Core 側の変更範囲を見て判断する。

### A案の候補

`RuntimePluginDefinition` に snapshot hook を追加する。

```ts
export interface RuntimePluginDefinition<TState = unknown> {
  readonly name: string
  readonly createInitialState: () => TState
  readonly createSnapshotState?: (state: TState) => unknown
}
```

`createRuntimeSnapshot()` が plugin definition を参照できるようにするには、snapshot API に plugin definitions を渡す必要がある。

```ts
createRuntimeSnapshot(state, {
  plugins: [createStdAudioPlugin()],
})
```

これは Core API 変更を伴うため、慎重に扱う。

### B案の候補

std-audio 側に helper を追加する。

```ts
createStdAudioSnapshotState(stdAudioState)
```

戻り値:

```ts
{
  bgm: stdAudioState.bgm,
  seEvents: [],
  voiceEvents: [],
  nextSeSequence: stdAudioState.nextSeSequence,
  nextVoiceSequence: stdAudioState.nextVoiceSequence,
}
```

app / save adapter 側が snapshot 保存前に呼び出す。

B案は Core API 変更が少ないが、save 処理が app 側に寄る。

## 32. v0.3 scope の最終イメージ

`.tzr`:

```tzr
#scene("main")

@startBgm("daily_theme")

:: Alice
こんにちは。
@voice("alice_001")

@se("door_open")

:: Bob
やあ。
@voice("bob_001")

@stopBgm
```

runtime state:

```ts
runtimeState.plugins.stdAudio = {
  bgm: null,
  seEvents: [
    {
      sequence: 1,
      assetId: "door_open",
    },
  ],
  voiceEvents: [
    {
      sequence: 1,
      assetId: "alice_001",
    },
    {
      sequence: 2,
      assetId: "bob_001",
    },
  ],
  nextSeSequence: 2,
  nextVoiceSequence: 3,
}
```

renderer / app 側:

```tsx
const audio = getStdAudioState(runtimeState)

if (audio.bgm === null) {
  stopCurrentBgm()
} else {
  playBgm(bgmAssets[audio.bgm.assetId])
}

for (const event of audio.seEvents) {
  if (event.sequence > lastConsumedSeSequence.current) {
    playSe(seAssets[event.assetId])
    lastConsumedSeSequence.current = event.sequence
  }
}

for (const event of audio.voiceEvents) {
  if (event.sequence > lastConsumedVoiceSequence.current) {
    stopCurrentVoiceIfNeeded()
    playVoice(voiceAssets[event.assetId])
    lastConsumedVoiceSequence.current = event.sequence
  }
}
```
