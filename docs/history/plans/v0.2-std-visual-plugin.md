# v0.2 std visual plugin 実装計画

> Status: historical implementation plan. References to legacy DSL syntax or

このドキュメントは `@tsuzuru/plugin-std-visual` の作業用実装計画である。  
利用者向けの正式仕様書ではない。

実装後、利用者向け仕様は `docs/plugins/std-visual.md` に整理し、設計判断は `docs/history/decisions/` 配下の decision record として整理する。

---

## 1. 位置付け

`@tsuzuru/plugin-std-visual` は、Tsuzuru v0.2 の正式 scope として実装する公式 plugin である。

Core には含めないが、Tsuzuru 公式の標準 plugin として扱う。  
サンプル plugin ではなく、事実上の標準ライブラリに近い位置付けとする。

### package

```txt
packages/plugin-std-visual
```

### package name

```txt
@tsuzuru/plugin-std-visual
```

### 命名方針

公式提供 plugin は `std` 系の命名にする。

例:

```txt
@tsuzuru/plugin-std-visual
```

---

## 2. Core との境界

Core は、シナリオ実行・状態管理・制御フローを担当する。

`@bg` / `@show` / `@hide` は Core command ではなく、plugin command として提供する。

理由:

- 背景や立ち絵は rendering / visual presentation に近い責務である
- Core は Preact / DOM / CSS / asset path / browser storage に依存しない方針である
- 将来的に別 renderer や別 visual plugin を許容しやすくするため

---

## 3. plugin の責務

`@tsuzuru/plugin-std-visual` は renderer 非依存にする。

### やること

- `@bg` / `@show` / `@hide` command を提供する
- visual state を `runtimeState.plugins.stdVisual` に保持する
- command argument の schema validation を行う
- 必要に応じて runtime diagnostics / logger 経由で warning を通知する
- state 取得用 helper を提供する

### やらないこと

- DOM / Preact component は提供しない
- 画像を直接描画しない
- asset resolver は内蔵しない
- assetId から画像 path への変換は行わない
- transition / duration は v0.2 初期では扱わない
- character ID / expression モデルは v0.2 初期では扱わない
- zIndex / order は v0.2 初期では扱わない

---

## 4. asset 解決方針

`@tsuzuru/plugin-std-visual` は state に `assetId` のみを保存する。

assetId から実ファイル path への変換は、app / renderer / example 側で行う。

例:

```ts
export const backgroundAssets = {
  classroom: "/assets/backgrounds/classroom.png",
  park: "/assets/backgrounds/park.png",
} as const

export const spriteAssets = {
  alice_smile: "/assets/sprites/alice_smile.png",
  bob_normal: "/assets/sprites/bob_normal.png",
} as const
```

plugin state には resolved path を保存しない。

---

## 5. runtime state

`@tsuzuru/plugin-std-visual` は、runtime state の plugin 領域に state を持つ。

```ts
runtimeState.plugins.stdVisual
```

plugin 側で独自 store は持たない。

理由:

- visual state は save/load 対象のゲーム状態である
- runtime state に集約した方が復元しやすい
- plugin 独自 store を持つと同期責務が増える

---

## 6. 初期 state

plugin 登録時に、以下の初期 state を用意する。

```ts
runtimeState.plugins.stdVisual = {
  background: null,
  sprites: {},
}
```

`background` は未設定状態を `null` で表す。

背景は v0.2 初期では単数扱いとする。  
複数背景・背景レイヤー合成は扱わない。

---

## 7. state 形状

### 初期状態

```ts
{
  background: null,
  sprites: {},
}
```

### 背景設定後

```ts
{
  background: {
    assetId: "classroom",
  },
  sprites: {},
}
```

### sprite 表示後

```ts
{
  background: {
    assetId: "classroom",
  },
  sprites: {
    alice_smile: {
      position: "center",
    },
  },
}
```

---

## 8. background

`background` は文字列ではなくオブジェクトで保持する。

```ts
background: {
  assetId: "classroom",
}
```

理由:

- 将来 `transition` / `variant` / `layer` などを追加しやすい
- v0.2 初期では `assetId` のみを持つ

未設定状態は `null` とする。

```ts
background: null
```

---

## 9. sprites

表示中の画像は `sprites` に保持する。

```ts
sprites: {
  alice_smile: {
    position: "center",
  },
}
```

`sprite` は、asset ID を画面上に配置した表示オブジェクトを表す。

### key

`sprites` の key は asset ID とする。

```ts
sprites: {
  alice_smile: {
    position: "center",
  },
}
```

各 sprite オブジェクト内に `assetId` は重複保持しない。

### 表示順

v0.2 初期では、`sprites` に `order` / `zIndex` は持たせない。

表示順・自然配置の判断は、runtime の順次実行により `sprites` に追加された順序を renderer / app 側が必要に応じて参照する。

ただし、state schema としては順序フィールドを定義しない。

### 複数人表示

複数人表示は、`sprites` に複数 asset ID を保持することで対応する。

```ts
sprites: {
  alice_smile: {
    position: "left",
  },
  bob_normal: {
    position: "right",
  },
}
```

同一 `position` に複数 sprite を表示することも許可する。

```ts
sprites: {
  alice_smile: {
    position: "center",
  },
  bob_normal: {
    position: "center",
  },
}
```

この場合、`position` は厳密な描画座標ではなく「配置希望」として扱う。  
実際の描画位置調整は renderer / app 側の責務とする。

## 10. command 一覧

v0.2 初期では以下を提供する。

```txt
@bg
@show
@hide
```

`@background` / `@showSprite` / `@hideSprite` のような冗長名にはしない。

---

## 11. `@bg`

### 構文

```tzr
@bg("classroom")
```

### 責務

`@bg` は、背景 asset ID を visual state に保存する。

### 引数

第1引数は暗黙的に `assetId` として扱う。

```tzr
@bg("classroom")
```

state 上では次のように正規化する。

```ts
background: {
  assetId: "classroom",
}
```

### 再指定

`@bg` は再指定時に常に `background` を上書き更新する。

```tzr
@bg("classroom")
@bg("park")
```

結果:

```ts
background: {
  assetId: "park",
}
```

同じ背景 ID を再指定した場合もエラーにしない。

```tzr
@bg("classroom")
@bg("classroom")
```

結果的に同じ値が再代入されるだけで、v0.2 初期では画面上の実質変化はない。

### transition

`transition` / `duration` は v0.2 初期では扱わない。  
将来拡張として検討する。

---

## 12. `@show`

### 構文

```tzr
@show("alice_smile")
@show("alice_smile", position: "center")
```

### 責務

`@show` は、sprite asset ID と position を visual state に保存する。

### 引数

第1引数は暗黙的に `assetId` として扱う。

```tzr
@show("alice_smile")
```

state 上では次のように正規化する。

```ts
sprites: {
  alice_smile: {
    position: "center",
  },
}
```

### position

`position` は v0.2 初期では以下の固定 enum とする。

```ts
"left" | "center" | "right"
```

ただし、将来的に renderer / app 側で拡張 position を扱える余地は残す。

### position 未指定時

`position` 未指定時は `"center"` をデフォルトにする。

```tzr
@show("alice_smile")
```

これは以下と同義。

```tzr
@show("alice_smile", position: "center")
```

### 同じ asset ID の再指定

同じ asset ID を再指定した場合は、既存の表示状態を上書き更新する。

```tzr
@show("alice_smile", position: "left")
@show("alice_smile", position: "center")
```

結果:

```ts
sprites: {
  alice_smile: {
    position: "center",
  },
}
```

エラーにはしない。

### 同じ position への複数表示

同じ `position` に複数 asset を表示することは許可する。

```tzr
@show("alice_smile", position: "center")
@show("bob_normal", position: "center")
```

state としては両方残す。

```ts
sprites: {
  alice_smile: {
    position: "center",
  },
  bob_normal: {
    position: "center",
  },
}
```

このときの実際の描画位置調整は renderer / app 側の責務とする。

---

## 13. `@hide`

### 構文

```tzr
@hide("alice_smile")
```

### 責務

`@hide` は、`@show` で指定した asset ID を指定して非表示にする。

### 引数

第1引数は暗黙的に `assetId` として扱う。

```tzr
@hide("alice_smile")
```

### state 操作

対象 sprite を `sprites` から削除する。

```ts
delete runtimeState.plugins.stdVisual.sprites["alice_smile"]
```

`visible: false` では残さない。

理由:

- `sprites` は「表示中の画像」を表す
- 非表示になったものを残すと、save/load や renderer 側の扱いが曖昧になる
- v0.2 初期では transition を扱わないため、削除で十分

### 存在しない asset ID

存在しない asset ID を指定した場合は no-op とする。

```tzr
@hide("unknown")
```

ただし、開発時に気づけるよう runtime warning を出す。

runtime error にはしない。

warning code:

```txt
plugin.stdVisual.hideTargetNotFound
```

warning は plugin handler が直接 `console.warn` するのではなく、runtime diagnostics / logger 経由で通知する。

---

## 14. validation

### 空文字 assetId

`assetId` の空文字は禁止する。

以下はすべて schema validation error とする。

```tzr
@bg("")
@show("")
@hide("")
```

背景解除が必要になった場合は、空文字ではなく、将来 `@clearBg` のような明示的 command を検討する。

### `@hide("unknown")` との違い

```tzr
@hide("unknown")
```

これは `assetId` としては有効な非空文字である。  
そのため command としては有効だが、実行時点で対象 sprite が存在しないため no-op + runtime warning とする。

```tzr
@hide("")
```

これは `assetId` として不正である。  
そのため schema validation error とする。

### 不正 position

`position` に `"left" | "center" | "right"` 以外の値が来た場合は schema validation error とする。

```tzr
@show("alice_smile", position: "top")
```

これは無効。

warning + fallback にはしない。  
typo を早期に検出するため、入力不正として扱う。

---

## 15. diagnostics / warning

runtime warning は、plugin handler が直接 `console.warn` しない。

runtime diagnostics / logger 経由で通知する。

例:

```ts
diagnostics.warn({
  code: "plugin.stdVisual.hideTargetNotFound",
  message: `std visual sprite "unknown" is not currently shown.`,
})
```

目的:

- テストしやすくする
- エディタ / GUI / デバッグ UI に流用しやすくする
- Core / macro / plugin 起因の diagnostics を区別しやすくする

## 16. public API

### plugin factory

`@tsuzuru/plugin-std-visual` は factory 関数を export する。

```ts
import { createStdVisualPlugin } from "@tsuzuru/plugin-std-visual"

const runtime = createRuntime({
  plugins: [
    createStdVisualPlugin(),
  ],
})
```

将来的に plugin options を追加しやすい形にする。

```ts
createStdVisualPlugin({
  // future options
})
```

### initial state

`createStdVisualPlugin()` が初期 state 定義も提供する。

plugin を登録すると、以下が初期化される。

```ts
runtimeState.plugins.stdVisual = {
  background: null,
  sprites: {},
}
```

### helper

renderer / app 側が state を扱いやすいように、薄い helper を提供する。

```ts
import { getStdVisualState } from "@tsuzuru/plugin-std-visual"

const visual = getStdVisualState(runtimeState)
```

`getStdVisualState(runtimeState)` は、`runtimeState.plugins.stdVisual` が未初期化の場合にエラーにする。

理由:

- plugin 未登録のまま renderer が stdVisual を読んでいる状態は設定ミスである
- 早期に検出した方がよい

## 17. export types

以下の runtime state 型を export する。

```ts
export type StdVisualState
export type StdVisualBackground
export type StdVisualSprites
export type StdVisualSprite
export type StdVisualSpritePosition
```

### 型名方針

`position` は sprite の配置希望を表すため、型名は `StdVisualSpritePosition` とする。

`background` の型名は `StdVisualBackground` とする。  
`StdVisualBackgroundState` のような冗長名にはしない。

`sprite` の型名は `StdVisualSprite` とする。  
`StdVisualSpriteState` のような冗長名にはしない。

`sprites` 全体の map 型は `StdVisualSprites` として export する。

### 取得方針

型は公開するが、state 取得は基本的に `getStdVisualState(runtimeState)` の利用を推奨する。

## 18. example

v0.2 では、`@tsuzuru/plugin-std-visual` の動作確認用 example として、既存の `examples/preact-basic` へ混ぜるのではなく、別 example を新設する。

```txt
examples/preact-std-visual
```

役割分担:

```txt
examples/basic
  core の最小確認

examples/preact-basic
  Preact runtime の基本確認

examples/preact-std-visual
  std visual plugin + Preact 描画の確認
```

### 画像素材

`examples/preact-std-visual` には、簡単な placeholder 画像ファイルを実際に用意する。

CSS の色付き box だけではなく、背景や sprite の描画確認ができる最低限の画像素材を含める。

例:

```txt
examples/preact-std-visual/public/assets/
  backgrounds/
    classroom.png
    park.png
  sprites/
    alice_smile.png
    bob_normal.png
```

### asset map

assetId と画像 path の対応表は `src/assets.ts` にまとめる。

```txt
examples/preact-std-visual/src/assets.ts
```

`VisualLayer.tsx` 内へ直接書かず、描画責務と asset map を分離する。

例:

```ts
export const backgroundAssets = {
  classroom: "/assets/backgrounds/classroom.png",
  park: "/assets/backgrounds/park.png",
} as const

export const spriteAssets = {
  alice_smile: "/assets/sprites/alice_smile.png",
  bob_normal: "/assets/sprites/bob_normal.png",
} as const
```

### VisualLayer

`VisualLayer` は example 内のサンプル実装として置く。

```txt
examples/preact-std-visual/src/VisualLayer.tsx
```

`@tsuzuru/preact` 側の公式コンポーネントには、少なくとも v0.2 初期では入れない。

理由:

- `@tsuzuru/plugin-std-visual` は renderer 非依存にする
- 公式描画コンポーネントまで固定しない
- CSS / asset map / 表示位置調整は app / renderer 側の責務にする

## 20. tests

test は plugin package の unit test を中心にする。

`examples/preact-std-visual` の自動テストは v0.2 初期では入れない。  
手動確認用に留める。

### test 対象

- `@bg` が `background` を更新する
- `@bg` が再指定時に上書きされる
- `@show` が `sprites` を追加する
- `@show` の `position` 未指定時に `"center"` になる
- `@show` が同じ asset ID を再指定した場合に上書き更新する
- `@hide` が `sprites` から対象を削除する
- `@hide` で存在しない asset ID を指定した場合、no-op + warning になる
- `@bg("")` は schema validation error
- `@show("")` は schema validation error
- `@hide("")` は schema validation error
- `@show("alice", position: "top")` は schema validation error
- `getStdVisualState(runtimeState)` は state 未初期化時にエラーにする

## 23. v0.2 初期の最終イメージ

`.tzr`:

```tzr
#scene("main")

@bg("classroom")
@show("alice_smile", position: "center")

:: Alice
こんにちは。

@show("bob_normal", position: "right")

:: Bob
やあ。

@hide("alice_smile")
```

runtime state:

```ts
runtimeState.plugins.stdVisual = {
  background: {
    assetId: "classroom",
  },
  sprites: {
    bob_normal: {
      position: "right",
    },
  },
}
```

renderer / app 側:

```tsx
const visual = getStdVisualState(runtimeState)

const backgroundSrc = visual.background
  ? backgroundAssets[visual.background.assetId]
  : null

const sprites = Object.entries(visual.sprites).map(([assetId, sprite]) => ({
  assetId,
  src: spriteAssets[assetId],
  position: sprite.position,
}))
```
