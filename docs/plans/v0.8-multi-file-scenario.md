# v0.8 Multi-File Scenario Plan

Status: implemented initial core and example support.

Tsuzuru multi-file scenarios are include based. A project is compiled from an
in-memory `documents` array with an `entryId`; core does not read the file
system or scan directories.

Initial scope:

- `#include("./path.tzr")` is a compile-time directive.
- Include paths resolve relative to the including `document.id`.
- Included documents are aggregated once, in include order after the entry
  document.
- Nested includes are supported.
- Missing and circular includes are validation errors.
- Project-level duplicate scene ids and duplicate label ids are validation
  errors.
- `-> labelName` jumps validate against the project-level label index.

Application screens are outside the DSL. Title, settings, load, backlog, and
gallery screens belong to TSX / HTML host code. `.tzr` files should focus on
the scenario body after game start.

Out of initial scope:

- `import`
- `@include`
- file-aware jumps such as `-> "./file.tzr#label"`
- label namespaces
- `tsuzuru.config.ts`
- CLI glob loading or directory scanning
- runtime current-file state
