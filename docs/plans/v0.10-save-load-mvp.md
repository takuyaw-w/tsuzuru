# v0.10 Save / Load MVP Plan

Status: implemented in `examples/dsl-v2-basic`.

## Goal

Add the minimum save/load flow needed for the runnable example to persist and
restore runtime progress.

The goal is to validate the existing `RuntimeSaveData` restore path in a real
host application. It is not to settle Tsuzuru's long-term storage adapter
design.

## Scope

- localStorage-backed save slots in `examples/dsl-v2-basic`
- three fixed save slots
- Title Continue from the latest save slot
- title-screen Load from a selected slot
- runtime Save and Load overlays that do not unmount `RuntimeApp`
- defensive validation of persisted data with `isRuntimeSaveData`
- example-level scenario identity and scenario version in save slot payloads
- migration from earlier example payloads and raw `RuntimeSaveData` payloads
- Playwright smoke coverage for Continue and basic save/restore

## Non-goals

- changes to `@tsuzuru/core`
- changes to `@tsuzuru/preact`
- changes to `@tsuzuru/standard-ui-preact`
- IndexedDB
- cloud save
- file save / Electron save
- screenshot thumbnails
- quick save / quick load
- auto save
- `create-tsuzuru` template propagation
- a standard UI SaveLoadPanel

## Save data identity

Save slot payloads use `ExampleSaveData.version: 2`. The payload includes the
example scenario identity:

```ts
{
  id: "tsuzuru.example.dsl-v2-basic",
  version: "1"
}
```

The localStorage key remains `tsuzuru:example-dsl-v2-basic:saves:v1` so existing
local saves can still be read. `version: 1` example save data and legacy raw
`RuntimeSaveData` payloads do not contain scenario identity, so the MVP migrates
them as data for the current example scenario and attaches the current identity.
`version: 2` payloads with a different scenario id or scenario version are not
exposed as load slots and are not considered by Title Continue.

This is intentionally scoped to the browser localStorage example. It is not a
formal Tsuzuru storage adapter, migration framework, or config schema.

## Verification

The implementation was verified with:

```sh
rtk pnpm --filter @tsuzuru/example-dsl-v2-basic typecheck
rtk pnpm --filter @tsuzuru/example-dsl-v2-basic build
rtk pnpm --filter @tsuzuru/example-dsl-v2-basic test
rtk pnpm --filter @tsuzuru/example-dsl-v2-basic test:ui
rtk git diff --check
```

The UI smoke test clears the example localStorage key before the run, verifies
that Continue is initially disabled, saves Slot 1 during runtime, returns to the
title screen, confirms Continue is enabled, and restores into the message
window.
