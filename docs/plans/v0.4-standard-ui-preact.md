# v0.4 standard-ui-preact 実装計画

> Status: historical implementation plan. References to legacy DSL syntax or
> removed examples predate the DSL v2 cleanup and are not current guidance.

このドキュメントは `@tsuzuru/standard-ui-preact` の作業用実装計画である。  
利用者向けの正式仕様書ではない。

利用者向け仕様は、実装後に `docs/ui/standard-ui-preact.md` または `docs/packages/standard-ui-preact.md` に整理する。  
設計判断は `docs/decisions/0006-standard-ui-preact.md` に整理する。

---

## 1. 位置付け

`@tsuzuru/standard-ui-preact` は、Tsuzuru v0.4 scope として実装する Preact 向け standard UI component package である。

Tsuzuru は `@tsuzuru/core`、`@tsuzuru/preact`、公式 plugin により、シナリオ実行と presentation state の管理までは提供している。

一方で、現状の `@tsuzuru/preact` は runtime と Preact を接続する adapter / hooks package であり、ノベルゲームとしての標準UI全体を提供する package ではない。

そのため v0.4 では、標準的な message window / choice layer / status display / shell を提供する package として `@tsuzuru/standard-ui-preact` を追加する。

### package

```txt
packages/standard-ui-preact
```

### package name

```txt
@tsuzuru/standard-ui-preact
```

### 命名理由

`@tsuzuru/preact-standard-ui` ではなく `@tsuzuru/standard-ui-preact` とする。

理由:

- `standard-ui` が主語になる
- Preact は実装 target として扱える
- `@tsuzuru/preact` の拡張 package だと誤解されにくい
- 将来的に optional non-Preact UI package を検討する場合も境界を保ちやすい

---

## 2. Core / Preact / UI の境界

### `@tsuzuru/core`

Core は、シナリオ実行、runtime state、runtime event、choice resolution、plugin command dispatch を担当する。

`@tsuzuru/core` は Preact / DOM / CSS に依存しない。

### `@tsuzuru/preact`

`@tsuzuru/preact` は、runtime と Preact を接続する adapter package である。

主な責務:

- `useRuntime`
- `RuntimeView`
- visible event handling
- auto-step behavior
- choice selection wiring
- save/load adapter utilities

`@tsuzuru/preact` は full game UI framework ではない。

### `@tsuzuru/standard-ui-preact`

`@tsuzuru/standard-ui-preact` は、Preact 製の standard UI component package である。

主な責務:

- message window
- choice layer
- status layer
- game shell
- runtime event から standard UI component への薄い adapter

`@tsuzuru/standard-ui-preact` は `useRuntime` を内包しない。  
runtime の生成、進行、save/load、plugin 登録は app 側または `@tsuzuru/preact` 側の責務とする。

## 3. dependency 方針

### dependencies

```txt
@tsuzuru/core
```

`RuntimeMessageLayer` が `RuntimeEvent` を受け取るため、`@tsuzuru/core` には依存する。

### peerDependencies

```txt
preact
```

`@tsuzuru/preact` と同様、Preact は peer dependency として扱う。

### devDependencies

```txt
preact
typescript
vitest
```

test / typecheck 用に dev dependency として Preact を持つ。

### 依存しない package

```txt
@tsuzuru/preact
@tsuzuru/plugin-std-visual
@tsuzuru/plugin-std-audio
```

理由:

- `@tsuzuru/standard-ui-preact` は UI部品提供に限定する
- `useRuntime` に依存しないことで、利用者側の runtime 接続方法を固定しない
- visual / audio plugin との統合は app / example 側に置く
- package 間の循環的・階層的な結合を避ける
- 将来の custom screen system と衝突しにくくする

## 8. MessageWindow

### 責務

`MessageWindow` は narration / dialogue を同一 component で扱う。

- `speaker` がある場合は dialogue
- `speaker` がない場合は narration

### API

dialogue:

```tsx
<MessageWindow
  speaker="Alice"
  lines={["Hello."]}
  onAdvance={onAdvance}
  canAdvance
  advanceHint="クリックで進む"
/>
```

narration:

```tsx
<MessageWindow
  lines={["It was raining."]}
  onAdvance={onAdvance}
  canAdvance
/>
```

想定 props:

```ts
export interface MessageWindowProps {
  readonly speaker?: string;
  readonly lines: readonly string[];
  readonly onAdvance?: () => void;
  readonly canAdvance?: boolean;
  readonly advanceHint?: string;
  readonly className?: string;
}
```

### lines

v0.4 初期では `string[]` のみ扱う。

```ts
readonly lines: readonly string[];
```

rich text / ruby / inline link / emphasis は扱わない。

理由:

- 現行 `RuntimeEvent` は `lines[].text` を持つ
- v0.4 では rich text DSL が存在しない
- UI component 側で先に rich text abstraction を入れると過剰設計になる

### click-to-advance

`MessageWindow` は click-to-advance の入り口を持つ。

仕様:

```txt
canAdvance=true かつ onAdvance が渡されている場合だけ clickable
window 全体クリックで onAdvance() を呼ぶ
canAdvance=false の場合はクリックしても進行しない
```

runtime の進行制御自体は持たない。  
受け取った `onAdvance` を呼ぶだけに留める。

### advance hint

`advanceHint` で文言を差し替え可能にする。

default:

```txt
Click to continue
```

仕様:

```txt
advanceHint は canAdvance=true かつ onAdvance がある場合だけ表示する
未指定時は "Click to continue"
```

### className

```txt
tzr-message-window
tzr-message-window--dialogue
tzr-message-window--narration
tzr-message-window--advanceable
tzr-message-window__speaker
tzr-message-window__lines
tzr-message-window__line
tzr-message-window__advance-hint
```

## 9. ChoiceLayer

### 責務

`ChoiceLayer` は choice question と選択肢一覧を表示する。

runtime の choice resolution は持たない。  
選択された index を `onChoice(index)` で通知する。

### API

```tsx
<ChoiceLayer
  question="What do you do?"
  choices={[
    { text: "Apologize" },
    { text: "Make a joke" },
  ]}
  onChoice={onChoice}
/>
```

想定 props:

```ts
export interface ChoiceLayerItem {
  readonly text: string;
}

export interface ChoiceLayerProps {
  readonly question: string;
  readonly choices: readonly ChoiceLayerItem[];
  readonly onChoice?: (itemIndex: number) => void;
  readonly className?: string;
}
```

### choices

`string[]` ではなく object 配列にする。

```ts
readonly choices: readonly ChoiceLayerItem[];
```

v0.4 初期では `ChoiceLayerItem` は `text` のみ持つ。

```ts
export interface ChoiceLayerItem {
  readonly text: string;
}
```

`disabled` / `id` / `visited` / `hint` は v0.4 では入れない。

理由:

- 現行 Runtime choice item と対応しやすい
- object 配列にすることで将来拡張余地は確保できる
- runtime に存在しない意味を UI へ先行実装しない

### onChoice

index ベースにする。

```ts
onChoice?: (itemIndex: number) => void;
```

理由:

- 現行 runtime の `resolveChoice(index)` と対応しやすい
- 既存 `RuntimeView` と同じ方向
- choice object / id ベースの解決は v0.4 では扱わない

### className

```txt
tzr-choice-layer
tzr-choice-layer__question
tzr-choice-layer__list
tzr-choice-layer__item
tzr-choice-layer__button
```

## 10. StatusLayer

### 責務

`StatusLayer` は runtime status を表示する。

用途:

```txt
waitClick
page
wait
error
unsupported
stop
end
debug status
```

### API

```tsx
<StatusLayer label="Page break" buttonLabel="Continue" onButtonClick={onContinue} />
<StatusLayer label="End" />
<StatusLayer label="Unsupported instruction: unknown" />
```

想定 props:

```ts
export interface StatusLayerProps {
  readonly label: string;
  readonly buttonLabel?: string;
  readonly onButtonClick?: () => void;
  readonly className?: string;
}
```

### button

`buttonLabel` と `onButtonClick` が両方ある場合だけ button を表示する。

```txt
buttonLabel && onButtonClick がある場合だけ button 表示
どちらか片方だけの場合は button を表示しない
```

理由:

- `waitClick` / `page` の continue UI に使える
- `error` / `end` / `stop` などでは button なしで使える
- component 数を増やさずに control status を表現できる

### className

```txt
tzr-status-layer
tzr-status-layer__label
tzr-status-layer__button
```

## 11. RuntimeMessageLayer

### 責務

`RuntimeMessageLayer` は `RuntimeEvent` を受け取り、standard UI component に振り分ける adapter component である。

leaf component は純粋 props にするが、adapter component だけは `RuntimeEvent` を知ってよい。

理由:

- leaf component の再利用性を保てる
- app 側で毎回 `RuntimeEvent` 変換処理を書かなくてよい
- `@tsuzuru/core` への依存を adapter に閉じ込められる
- `@tsuzuru/preact` には依存しない

### API

```tsx
<RuntimeMessageLayer
  event={event}
  onAdvance={onAdvance}
  onChoice={onChoice}
  onContinue={onContinue}
  canAdvance
  advanceHint="クリックで進む"
  continueLabel="Continue"
/>
```

想定 props:

```ts
export interface RuntimeMessageLayerProps {
  readonly event: RuntimeEvent;
  readonly onChoice?: (itemIndex: number) => void;
  readonly onAdvance?: () => void;
  readonly onContinue?: () => void;
  readonly canAdvance?: boolean;
  readonly showTransientStatus?: boolean;
  readonly advanceHint?: string;
  readonly continueLabel?: string;
  readonly className?: string;
}
```

### default labels

```txt
advanceHint: "Click to continue"
continueLabel: "Continue"
```

### event mapping

#### narration

```txt
narration -> MessageWindow
```

Mapping:

```ts
{
  lines: event.lines.map((line) => line.text)
}
```

#### dialogue

```txt
dialogue -> MessageWindow
```

Mapping:

```ts
{
  speaker: event.speaker,
  lines: event.lines.map((line) => line.text)
}
```

#### choice

```txt
choice -> ChoiceLayer
```

Mapping:

```ts
{
  question: event.question,
  choices: event.items.map((item) => ({ text: item.text }))
}
```

#### waitClick

```txt
waitClick -> StatusLayer
```

Mapping:

```tsx
<StatusLayer
  label="Waiting for click"
  buttonLabel={continueLabel}
  onButtonClick={onContinue}
/>
```

#### page

```txt
page -> StatusLayer
```

Mapping:

```tsx
<StatusLayer
  label="Page break"
  buttonLabel={continueLabel}
  onButtonClick={onContinue}
/>
```

#### wait

```txt
wait -> StatusLayer
```

Mapping:

```tsx
<StatusLayer label={`Waiting ${event.durationMs}ms`} />
```

#### error

```txt
error -> StatusLayer
```

Mapping:

```tsx
<StatusLayer label={event.message} />
```

#### unsupported

```txt
unsupported -> StatusLayer
```

Mapping:

```tsx
<StatusLayer label={`Unsupported instruction: ${event.instructionType}`} />
```

#### stop

```txt
stop -> StatusLayer
```

Mapping:

```tsx
<StatusLayer label="Stopped" />
```

#### end

```txt
end -> StatusLayer
```

Mapping:

```tsx
<StatusLayer label="End" />
```

### transient event policy

以下の runtime events は、デフォルトでは表示しない。

```txt
scene
label
jump
if
state
pluginCommand
```

理由:

- これらは runtime の進行・状態変化・presentation state 更新を表す transient event である
- game UI 上に `Plugin command: bg` のような表示が出ると不自然
- visual / audio plugin command は別 layer が state を読んで表示・再生する

ただし debugging 用に表示できる余地は残す。

```ts
showTransientStatus?: boolean;
```

`showTransientStatus=true` の場合のみ、以下を `StatusLayer` で表示する。

```txt
scene -> Scene: <id>
label -> Label: <id>
jump -> Jump: #<label>
if -> If: true/false (<branch>)
state -> <command>: <name> = <value>
pluginCommand -> Plugin command: <name>
```

### null rendering

`showTransientStatus=false` で transient event を受け取った場合、`RuntimeMessageLayer` は `null` を返してよい。

## 18. example VisualLayer

`VisualLayer` は example-local 実装にする。

```txt
examples/standard-ui-preact/src/VisualLayer.tsx
```

package には含めない。

理由:

- `@tsuzuru/standard-ui-preact` は `@tsuzuru/plugin-std-visual` に依存しない
- asset resolver は app 側の責務
- visual の描画方法は作品や renderer によって異なる

### behavior

```txt
stdVisual state を読む
background assetId を asset map で path に変換する
sprites を asset map で path に変換する
画像があれば img として表示する
画像未配置や asset 未定義の場合は fallback box を表示して app を落とさない
```

### asset map

```ts
export const backgroundAssets = {
  classroom: "/assets/backgrounds/classroom.png",
} as const;

export const spriteAssets = {
  alice_smile: "/assets/sprites/alice_smile.png",
```

## 19. example AudioLayer

`AudioLayer` は example-local 実装にする。

```txt
examples/standard-ui-preact/src/AudioLayer.tsx
```

package には含めない。

理由:

- `@tsuzuru/standard-ui-preact` は `@tsuzuru/plugin-std-audio` に依存しない
- audio playback は browser autoplay 制約を受ける
- asset resolver / playback policy / volume / fade は app 側の責務
- package の責務を message / choice / status UI に限定する

### behavior

```txt
stdAudio state を読む
BGM / SE / Voice の assetId と sequence を表示する
asset map に path が定義されていて、実ファイルが配置されていれば再生を試みる
音声ファイル未配置 / autoplay reject / load error では app を落とさない
画面上 notice + console warning に留める
```

### asset map

```ts
export const bgmAssets = {
  main_theme: "/assets/audio/bgm/main_theme.mp3",
} as const;

export const seAssets = {
  click: "/assets/audio/se/click.mp3",
} as const;

export const voiceAssets = {
  alice_001: "/assets/audio/voice/alice_001.mp3",
} as const;
```

### audio files

音声ファイルは同梱しない。

README に以下を明記する。

```txt
音声ファイルは同梱しません。
再生を確認する場合は、任意の音声ファイルを public/assets/audio/ 配下に配置してください。

例:
public/assets/audio/bgm/main_theme.mp3
public/assets/audio/se/click.mp3
public/assets/audio/voice/alice_001.mp3
```

## 24. design summary

v0.4 の判断をまとめる。

```txt
@tsuzuru/standard-ui-preact は、Preact 製の標準UI component package とする。

UI部品提供のみを責務とし、useRuntime は内包しない。
std-visual / std-audio にも依存しない。
@tsuzuru/preact にも依存しない。

leaf component は純粋 props を受け取る。
RuntimeEvent を知るのは RuntimeMessageLayer のみとする。

GameShell は root layout container に限定する。
MessageWindow は narration / dialogue を同一 component で扱う。
ChoiceLayer は object 配列の choices を受け取り、index ベースで onChoice を呼ぶ。
StatusLayer は label と optional button を表示する。
RuntimeMessageLayer は RuntimeEvent を各 UI component に変換する。

CSS は package から提供する。
theme system は v0.4 では作らない。

examples/standard-ui-preact では std-visual / std-audio と統合する。
ただし VisualLayer / AudioLayer は example-local に置く。
画像生成は別タスクにする。
音声ファイルは同梱しないが、配置されていれば再生を試みる。
```
