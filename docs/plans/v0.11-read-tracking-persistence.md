# v0.11 Read Tracking Persistence Plan

Status: implemented in `examples/dsl-v2-basic`.

## Goal

Persist the example Read Tracking state so Skip Mode can continue using known
read narration and dialogue after a page reload or app restart.

This is an example-level browser persistence step. It is not a standard package
hook or a general save data migration framework.

## Scope

- localStorage-backed Read Tracking in `examples/dsl-v2-basic`
- `narration` and `dialogue` read entry keys only
- scenario identity validation using the example scenario id and version
- defensive JSON and payload validation
- duplicate read key removal on restore
- Skip Mode continuing to use the restored read set
- focused unit coverage for read key generation, serialization, validation, and
  localStorage round trip

## Non-goals

- changes to `@tsuzuru/core`
- changes to `@tsuzuru/preact`
- changes to `@tsuzuru/standard-ui-preact`
- scene tracking
- choice tracking
- gallery unlocks
- achievements
- package-level Read Tracking hooks
- `create-tsuzuru` template propagation
- Skip Mode behavior redesign

## Storage Format

Read Tracking is stored separately from save slots under:

```txt
tsuzuru:example-dsl-v2-basic:read-tracking:v1
```

The payload is:

```ts
{
  version: 1,
  scenario: {
    id: "tsuzuru.example.dsl-v2-basic",
    version: "1"
  },
  readEntryKeys: ["narration:...", "dialogue:mio:..."]
}
```

Only `narration` and `dialogue` entries are written because those are the only
events tracked by the existing Read Tracking MVP. Keys continue to be generated
from message content through `createReadEntryKey()`.

## Scenario Identity

On load, payloads must match both the current scenario id and current scenario
version. Mismatched data is treated as unavailable and the example falls back to
an empty Read Tracking state.

Invalid JSON, malformed payloads, unavailable localStorage, and storage write
errors do not crash the app. The example keeps the in-memory state and falls
back to an empty restored state when loading fails.

## Runtime Wiring

`RuntimeApp` initializes Read Tracking from localStorage. When a trackable
message becomes visible, it first checks whether the key was already read, then
marks the key read and saves the updated state.

That preserves the existing Skip Mode requirement: a first-time message is not
skipped during the same display, while messages that were already read before
display can be skipped.
