# v0.1.0 Initial Publish Readiness Plan

Status: draft execution checklist.

This checklist prepares Tsuzuru packages for the initial npm release as
`v0.1.0`. It does not publish, tag, run publish dry-runs, or create GitHub
releases.

## Publish Targets

Publishable packages:

- `packages/core` publishes as `@tsuzuru/core`
- `packages/config` publishes as `@tsuzuru/config`
- `packages/cli` publishes as `@tsuzuru/cli`
- `packages/preact` publishes as `@tsuzuru/preact`
- `packages/standard-ui-preact` publishes as `@tsuzuru/standard-ui-preact`
- `packages/plugin-std-visual` publishes as `@tsuzuru/plugin-std-visual`
- `packages/plugin-std-audio` publishes as `@tsuzuru/plugin-std-audio`
- `packages/create-tsuzuru` publishes as `create-tsuzuru`

Publish excluded:

- root `tsuzuru` package, which must stay `private: true`
- `examples/dsl-v2-basic`
- docs, plans, tests, and repository-only tooling

## npm Assumptions

- Scoped packages publish under the `@tsuzuru` npm org.
- Scoped packages require public access, so each `@tsuzuru/*` package should set
  `publishConfig.access` to `public`.
- `create-tsuzuru` is unscoped, so it does not need `publishConfig.access`.
- Publishable monorepo packages keep the pnpm workspace protocol during
  development. Internal `@tsuzuru/*` dependencies should use `workspace:^`.
- Package names and npm org ownership are confirmed for the initial publish
  preparation.
- The repository uses the MIT License, and publishable packages declare
  `"license": "MIT"`.

## Publish Command Policy

Do not publish Tsuzuru packages with direct npm package-path commands such as
`npm publish ./packages/core`. Direct npm publish does not perform pnpm
workspace protocol conversion, so `workspace:*` or other workspace protocol
specifiers can remain in the published `package.json`.

Use pnpm publish from the workspace instead:

```sh
pnpm --filter @tsuzuru/core publish
pnpm --filter @tsuzuru/config publish
pnpm --filter @tsuzuru/cli publish
pnpm --filter @tsuzuru/preact publish
pnpm --filter @tsuzuru/standard-ui-preact publish
pnpm --filter @tsuzuru/plugin-std-visual publish
pnpm --filter @tsuzuru/plugin-std-audio publish
pnpm --filter create-tsuzuru publish
```

pnpm publish converts workspace protocol dependencies to publishable semver
ranges based on the referenced workspace package versions. For the v0.1.0
release, `workspace:^` internal dependencies should publish as `^0.1.0`.

To confirm publish-time manifest conversion without publishing, use pnpm publish
dry-runs:

```sh
pnpm --filter @tsuzuru/core publish --dry-run
pnpm --filter @tsuzuru/config publish --dry-run
pnpm --filter @tsuzuru/cli publish --dry-run
pnpm --filter @tsuzuru/preact publish --dry-run
pnpm --filter @tsuzuru/standard-ui-preact publish --dry-run
pnpm --filter @tsuzuru/plugin-std-visual publish --dry-run
pnpm --filter @tsuzuru/plugin-std-audio publish --dry-run
pnpm --filter create-tsuzuru publish --dry-run
```

## Pack Dry-Run

Run from the repository root after dependencies are installed and packages are
built:

```sh
pnpm --filter @tsuzuru/core pack --dry-run
pnpm --filter @tsuzuru/config pack --dry-run
pnpm --filter @tsuzuru/cli pack --dry-run
pnpm --filter @tsuzuru/preact pack --dry-run
pnpm --filter @tsuzuru/standard-ui-preact pack --dry-run
pnpm --filter @tsuzuru/plugin-std-visual pack --dry-run
pnpm --filter @tsuzuru/plugin-std-audio pack --dry-run
pnpm --filter create-tsuzuru pack --dry-run
```

Equivalent root helper:

```sh
pnpm run pack:dry-run
```

`pack:dry-run` is still useful for checking package file lists, `files`
patterns, generated `dist` outputs, CLI bins, and bundled templates. It is not
the release approval step for workspace protocol conversion; use the
`pnpm --filter <package> publish --dry-run` commands above for that check.

Confirm each package includes:

- `package.json`
- `README.md`
- compiled JavaScript and `.d.ts` files under the exported paths
- CLI `bin` targets for `@tsuzuru/cli` and `create-tsuzuru`
- `@tsuzuru/standard-ui-preact/style.css`
- `create-tsuzuru` `templates/basic/**`, including asset `.gitkeep` files

Confirm each package excludes:

- repository docs and plans
- tests
- unrelated examples
- source-only files that are not part of the public package

```sh
rtk pnpm install --frozen-lockfile

rtk pnpm lint
rtk pnpm check
rtk pnpm test
rtk pnpm run typecheck

rtk git diff --check
```

## Known Blockers

- Generated projects from `create-tsuzuru` use semver Tsuzuru dependencies.
  Those installs can fail until the matching package versions are published.
- `create-tsuzuru` supports only the basic template.
- There is no Vite plugin yet.
- There are no `tsuzuru dev` or `tsuzuru build` commands yet.
- Provenance configuration has not been decided.
- Actual package publish is not part of this preparation task.

## Remaining v0.1.0 Publish Work

After the version and release notes preparation is merged, the remaining publish
work is:

1. Run the final checks on the release branch or clean checkout.
2. Decide whether the initial pnpm publish uses provenance, and document the
   exact publish command set before running it.
3. Create `git tag v0.1.0` only after final checks pass.
4. Create GitHub release notes from `docs/releases/v0.1.0.md`.
5. Publish the npm packages with `pnpm --filter <package> publish` in dependency
   order:
   `@tsuzuru/core`, `@tsuzuru/config`, `@tsuzuru/cli`, `@tsuzuru/preact`,
   `@tsuzuru/standard-ui-preact`, `@tsuzuru/plugin-std-visual`,
   `@tsuzuru/plugin-std-audio`, then `create-tsuzuru`.
